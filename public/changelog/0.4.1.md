## 0.4.1 — 9 октября 2026

### Связь с сервером
- Если сервер недоступен, приложение больше не отправляет вас на страницу входа и не сбрасывает вход. Вверху появляется сообщение «Нет связи с сервером. Вход сохранён, переподключаемся.» с кнопкой «Повторить», а когда связь вернётся, оно исчезает само.
- Если сервер недоступен при открытии приложения, показывается страница ожидания, а как только связь появляется, вы попадаете на ту страницу, которую открывали.
- Вход сбрасывается только тогда, когда сервер явно отклонил сессию. Обрыв связи, ошибка шлюза или ошибка сервера при проверке входа его не отменяют: в последнем случае страница предложит повторить попытку.
- Нестабильное соединение больше не принимается за отсутствие связи. Сообщение появляется, только когда подряд не ответили несколько проверок, а единичный оборванный запрос или сбой одного обработчика его не вызывает.
- Обновление входа выполняется одним запросом за раз: сервер отзывает всю сессию, если один и тот же токен обновления предъявить дважды.

### Сервер и API
- Каждый сервис (user, event, org, profile, geo, notify, bot и mail) отдаёт проверку живости GET /сервис/v1/health: состояние, имя сервиса и версию. Она описана в схемах v1 и есть в клиенте фронтенда.
- Контейнеры в docker-compose проверяются по этим адресам, а контейнер aef — по /user/v1/health. Traefik направляет запросы только на здоровые контейнеры.
- У сервиса mail появился HTTP-интерфейс v1: пока в нём только проверка живости.
